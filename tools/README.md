# tools

Внешние утилиты, которые работают **вне** игрового скрипта.

## `screeps-watchdog.mjs`

Сторож аккаунта: следит за `world-status` и возвращает аккаунт в игру,
если он остался без спавна.

### Зачем

Скрипт игрока в Screeps выполняется только для активных аккаунтов. Активность
определяется наличием комнаты или крипа, поэтому:

* если у игрока забрали комнату и он нажал «Respawn» (или сервер сделал это
  сам), аккаунт получает статус `empty` — «респавн прошёл, спавн ещё не
  поставлен»;
* пока спавн не поставлен, у аккаунта нет ни комнаты, ни крипа → движок
  перестаёт запускать игровой код: `Memory` замораживается, счётчик тиков
  перестаёт расти, бот молчит;
* выйти из этого состояния **самим кодом бота невозможно**: чтобы завести
  крипа, нужен спавн, а чтобы поставить спавн, нужен игрок.

Именно так выглядела остановка 25.09 → 23.10.2026: аккаунт `katarsin`
(GCL 118408) провисел 28 суток в статусе `empty`, игровой скрипт не отработал
ни одного тика. Починить это мог только внешний процесс — вручную или этим
сторожем.

### Что делает

| `world-status` | Действие |
| --- | --- |
| `normal` | всё в порядке, выходим |
| `lost` | `POST /api/user/respawn`, ждём `respawnPenalty` + 5 с, дальше как в `empty` |
| `empty` | подбираем комнату со свободным контроллером и ставим спавн: `POST /api/game/place-spawn` |

При выборе комнаты скрипт:

1. берёт комнаты из `GET /api/user/world-start-room` и их соседей
   (радиус 2) на том же шарде;
2. оставляет только комнаты, где есть **свободный контроллер**: уровень 0,
   без владельца и без резервации — только такой контроллер сервер отдаёт
   при `place-spawn`;
3. выбирает позицию спавна рядом с источником и контроллером, с запасом
   места под extensions (кольцо 2..6), не ближе двух клеток к выходу из комнаты
   (сервер такое отклоняет).

### Особенности API, на которые стоит опираться

* `POST /api/user/respawn` отвечает `{"error":"invalid status"}` при статусе
  `empty` — респавн в этом состоянии не нужен, нужен `place-spawn`.
* `POST /api/game/place-spawn` требует поле `shard`, иначе
  `{"error":"invalid shard"}`.
* Комнаты из `world-start-room` могут оказаться комнатами Source Keeper'ов
  без контроллера — тогда сервер отвечает `{"error":"invalid room"}`, и
  скрипт переходит к соседним комнатам.
* `world-status` считается по наличию объектов аккаунта, а не по наличию
  комнаты в `Game.rooms`.

### Запуск

```bash
SCREEPS_TOKEN=<токен> node tools/screeps-watchdog.mjs          # проверить и починить
SCREEPS_TOKEN=<токен> node tools/screeps-watchdog.mjs --check  # только диагностика
SCREEPS_TOKEN=<токен> node tools/screeps-watchdog.mjs --json   # машинный вывод
```

Требуется Node 18+ (глобальный `fetch`); внешних зависимостей нет.

Коды возврата: `0` — всё в порядке (или починили), `1` — починить не удалось,
`2` — неизвестный статус.

### GitHub Actions

В репозитории есть `.github/workflows/screeps-watchdog.yml`: он запускает
сторож каждые 3 часа. Токен нужно положить в секрет репозитория:

**Settings → Secrets and variables → Actions → New repository secret →
`SCREEPS_TOKEN`**

Секрет хранится в GitHub, в код не попадает. Скрипт можно запускать и вручную
(вкладка **Actions → Screeps Watchdog → Run workflow**).

### Локальный cron

Если нет желания отдавать токен GitHub:

```cron
*/30 * * * * SCREEPS_TOKEN=<токен> /usr/bin/node /path/to/screeps-code/tools/screeps-watchdog.mjs --check
```
